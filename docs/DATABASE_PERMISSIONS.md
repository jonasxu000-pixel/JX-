# 云数据库权限配置

## RC12 数据分层

- `rooms`：云函数专用真实房间，包含玩家 OpenID、房间号、棋盘和裁判状态。
- `roomViews`：客户端实时监听的脱敏视图，只包含棋盘、回合、胜负和双方公开展示资料。
- 六位房间号只用于调用 `roomAction.joinRoom`；创建或加入成功后，云函数返回随机 `viewId`。
- 客户端不能用房间号直接读取真实房间，也不能直接写入任何集合。

## rooms 集合权限

```json
{
  "read": false,
  "write": false
}
```

## roomViews 集合权限

```json
{
  "read": true,
  "write": false
}
```

`roomViews` 文档 ID 是 36 位随机十六进制字符串，不使用可枚举的六位房间号；视图中不得出现 OpenID。该集合仅保存对局所需的公开资料与棋局状态，不应写入手机号、真实姓名等隐私数据。

## 房间生命周期

- 等待房间 30 分钟无活动后过期。
- 对局中或已结束房间 6 小时无活动后过期。
- 每次启动云端预热或创建房间时，云函数会分批清理过期的真实房间和公开视图。
- 加入、落子、投降、再战和退出发现房间过期时，会立即关闭房间并删除对应视图。

## 正式环境配置步骤

1. 在微信开发者工具中打开“云开发 -> 数据库”。
2. 创建 `roomViews` 集合。
3. 将 `rooms` 权限设置为客户端不可读、不可写。
4. 将 `roomViews` 权限设置为客户端可读、不可写。
5. 部署最新 `roomAction` 云函数。

## 验证方法

1. 创建房间成功，返回六位 `roomId` 和随机 `viewId`。
2. `rooms` 中保存身份数据，客户端直接读取必须失败。
3. `roomViews` 中不包含 `openId`，客户端可通过 `viewId` 监听。
4. 加入、落子、胜负、投降、再战和退出均正常同步。
5. 客户端直接写入两个集合都必须失败。
6. 房主退出后，真实房间和公开视图同时删除。
