## 1. 落子后裁判前提

`utils/gomokuRules.js:129` 明确写明落子后调用。`lineLength` 以当前点计数为 1，因此它不承担试落子功能；连珠棋形枚举又读取实际棋盘，所以落子前调用在不同模式下还可能出现不同偏差。

最小复现（坐标从 0 起）：

```js
const g = require('./utils/gomokuRules');
const b = Array.from({ length: 15 }, () => Array(15).fill(0));
[3, 4, 5, 6].forEach(c => { b[7][c] = 1; });
console.log(b[7][7]);                              // 0：尚未落子
console.log(g.adjudicate(b, 7, 7, 1).win);         // true：将指定点视为已落子
b[7][7] = 1;
console.log(g.adjudicate(b, 7, 7, 1).win);         // true：契约内结果正确
```

另一个最小对照：在 `[7,6]`、`[7,8]`、`[6,7]`、`[8,7]` 放黑子，裁判 `[7,7]`。落子前连珠返回 `foul:null`，写入黑子后正确返回 `doubleThree`。因此不能把这个接口当作落子预测接口。

正常调用证据：

- 同屏 `LocalGameScene.handleTouch`：第 216 行写入棋子，第 225 行才调用 `adjudicate`。
- 好友服务 `placePieceForOpenId`：第 419 行写入 `nextBoard`，第 421 行才调用 `adjudicate`，结果通过房间事务保存。
- 全仓搜索只有上述两个业务胜负裁判调用点。好友客户端不自行预测胜负，在线场景只调用开局检查。

结论：契约前提真实存在，当前正常业务没有违反它。没有理由把函数改成自行补落子；这种改动还会改变已落子调用语义。

## 2. 缺少 rules 的异常

最小复现：

```js
const g = require('./utils/gomokuRules');
const b = Array.from({ length: 15 }, () => Array(15).fill(0));
g.openingError(b, 0, 0, 1, undefined); // TypeError
g.openingError(b, 0, 0, 1, { openingCenter: false }); // ''
```

正常调用证据：

- 同屏：构造器第 25 行从 `matchRules.normalize` 初始化对象，第 204 行传入 `this.rules`。
- 好友客户端：第 56 行初始化对象，第 248 行从房间数据规范化（缺失时传入兜底对象），第 697 行传入 `this.rules`。
- 好友云端：第 415 行使用服务端 `matchRules.normalize(room.rules)`，第 416 行传入结果；该规范化函数对旧版或缺失输入返回 `EMPTY_RULES` 对象。

结论：异常可复现，正常路径不可复现。当前接口签名要求 `rules`，未找到允许省略它的设计或调用证据。合理改进是明确必填参数与添加契约测试，不能直接据此认定应加默认对象。

## 3. 双三边界与规则依据

按 [RIF 规则第 3 条与 9.3 条](https://www.renju.net/rifrules/) 检查“三”的形成、直四两个胜点、禁手延伸导致的假三，以及递归禁手。另以 [联盟假三与禁手教程](https://www.renju.net/advanced/) 的说明核对测试期望。

新增固定案例覆盖：角落两条被边界封闭的三、贴边只有一条真三、离边一格的真双三、近边跳三、同线假三的长连端点、活三/活四不重复计数、合法四三、同向双四、边缘单端四、三方向双三、延伸同时成五、延伸双四假三、递归双三假三；每例执行旋转和镜像。

此外新增测试参考判定：它尝试每个空点，扫描形成的最大连续段及延伸合法性；生产代码则枚举五格/六格窗口。两种生成方式分别实现，并逐项比较结果。参考判定是本轮测试代码，不是第三方认证裁判。

结果：

- **65,529 个单线局面**对照一致。中心覆盖半径 5、边缘 8 个落点覆盖半径 4 的空/黑/白三值枚举，其余格点为空；不是全部二维棋盘枚举。
- **112 个固定边界案例**对照一致，包含上述 14 组的旋转/镜像；客户端及云端裁判返回一致，输入棋盘不被修改。
- **1,000 次固定种子跨方向合成局面**与参考判定一致。这些局面没有全部经过合法落子历史筛选，不当作真实对局证据。
- **3 种边缘场景**从空盘经实际同屏场景交替落黑白子完成：角落合法、贴边合法、离边一格双三判负。该测试使用桌面运行时和模拟触摸，不是手机验收。

结论：没有误判反例；原边缘覆盖缺口属实，补充测试有收益。没有证据支持修改双三算法，也不能宣称其所有可能局面均已证明正确。

## 4. 五连与双四的运行证据

原有 `scripts/verify-advanced-rules.js` 覆盖双三、交叉双四、同向双四、长连、假三、五子优先与白棋长连；`scripts/verify-room-action.js` 覆盖通过实际云函数入口的落子、黑白获胜、结束后禁止继续落子，以及 v2 禁手结算，数据库使用本地模拟。

本轮两个既有脚本均复跑通过。新增 **48 个五连/长连案例**覆盖四方向、黑白双方、自由/恰好五子/连珠三种模式，以及以棋盘边缘为端点的连续段。单线枚举也对五连和双四进行了参考判定比较。

结论：已有运行佐证，覆盖内结果正确；未发现五连或双四缺陷。
