## 2026-06-08 进展

### 已完成

- 提交稳定点：`feat: add cloud room sync foundation`
- 联机棋盘改为受控模式：
  - 在线模式下棋盘组件只上报点击坐标
  - 不再提前本地落子
  - 棋盘状态统一由房间监听同步写入
- 游戏页联机逻辑收敛：
  - 前端不再在线判断胜负并二次提交
  - 云函数 `placePiece` 作为唯一落子与胜负裁判
  - 增加在线落子提交防抖，避免连续点击重复提交
  - 对局结束后双方可看到“你获胜/对手获胜”结果弹窗
- 修复进度文件乱码，恢复为唯一可读进度来源
- 服务端落子写入增加条件更新：
  - 只有房间仍为 `playing`
  - 只有仍轮到当前角色
  - 只有尚未产生赢家
  - 避免同一回合重复请求覆盖房间状态

### 待验证

- 本地规则模拟已通过：
  - 房主黑棋五连后 `winner=host`、`status=finished`
  - 加入者白棋五连后 `winner=guest`、`status=finished`
  - 非当前回合落子、重复位置落子、结束后继续落子均会被拒绝
  - 条件更新冲突会返回“房间状态已变化，请刷新后重试”
  - 可复用脚本：`node scripts/verify-room-action.js`
- 微信开发者工具双账号联调：
  - 房主创建房间，加入者加入房间
  - 房主只能下黑棋，加入者只能下白棋
  - 双方轮流落子，非当前回合无法落子
  - 双方棋盘实时一致
  - 黑棋/白棋分别五连后，双方都显示胜负结果
- 云函数 `roomAction` 需要重新上传部署后再验收

## 当前风险

- 云函数落子目前依赖服务端校验和前端防抖，尚未做数据库事务级并发锁。
- 小程序云开发监听依赖数据库权限配置，若监听失败需优先检查 `rooms` 集合权限。
- 对手离开后的重开/继续等待策略仍较简单，后续可单独优化。
